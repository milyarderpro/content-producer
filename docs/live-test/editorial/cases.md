# Kartu prompt evaluasi editorial dan penyimpanan draft — v7 integrated payload (historis)

**Prosedur aktif mulai 28 Oktober 2026:** [uji utama direct-save v1](main-direct-save-v1.md) menetapkan matriks, revisi prompt ringkas, urutan dan batas Write untuk 30 kasus. Seluruh prompt v7 di bawah tetap arsip dan **tidak dikirim**. ID kasus, tema, empat kasus terpandu dan dua kasus implisit per format tetap dipertahankan; jangan mencampur hasil v7 dengan kohort baru.

**Status historis v7:** kelima pilot baseline, retest `direct-save-01` yang tertahan, serta dua retest `v026` yang menyimpan draft telah dicoba. Tiga puluh prompt utama di bawah adalah matriks rencana awal dengan instruksi GO historis, **bukan antrean live aktif dan bukan prompt siap-tempel untuk alur direct-save sekarang**. Keputusan lama untuk menunda 30 ada di [ringkasan saat itu](summary.md#keputusan-eksekusi-final--hemat-waktu); keputusan membuka kohort baru dan prompt operasionalnya kini berada di [direct-save v1](main-direct-save-v1.md). Jangan memakai teks `v7` apa adanya. Semua paragraf serta prompt di bawah heading ini menjelaskan **prosedur historis v7**, bukan instruksi pelaksanaan baru.

Jalankan hanya setelah [Page uji](page-setup.md) dibuat dengan izin spesifik dan konfigurasi dibaca kembali. Reviewer mengganti `{{TEST_PAGE_PUBLIC_ID}}` dengan public ID Page uji yang terbukti, lalu memberi pemilik **satu prompt siap-tempel** untuk satu chat baru dengan hanya plugin PRIVATE Content Producer. Jangan menempel heading `Format diharapkan` karena kasus implisit tidak boleh membocorkan jawaban. Reviewer menyimpan prompt final dan hasil; pemilik hanya menyalin prompt dan meneruskan respons chat pilot. Setiap prompt **menargetkan satu draft tersimpan hanya bila fakta layak**. Plugin meneliti, memfinalkan set fakta dan teks editorial `content_payload`, serta memastikan kecocokan renderer **sebelum** satu checkpoint GO. GO yang diteruskan pemilik mengizinkan satu reservasi dan satu `save_post` untuk set fakta serta teks yang tidak berubah, bukan persetujuan massal; ID/token binding dan metadata teknis dari respons server baru diisi setelah reservasi. `trivia_release_facts`, revisi, approval dan publikasi tetap di luar izin. Jika izin ditolak, bukti tidak memadai, atau alur terhenti, reviewer mencatat tahap dan state; jangan mengklaim draft tersimpan tanpa `get_post` readback. Lihat [protokol](protocol.md). Semua naskah harus orisinal, bukan parafrasa dataset. `v4` adalah prompt historis pilot awal; jangan menimpa record tersebut dengan teks `v7`.

Pilot dan empat kasus eksplisit per format adalah permintaan **terpandu**: prompt sengaja menyebut format dan sebagian aturan kualitas. Dua kasus implisit per format adalah permintaan **minimal** dalam aspek editorial: hanya topik/tujuan, `en-US`, sumber per klaim, dan Page uji; langkah validasi payload/Write sama untuk semua kasus dan tidak membocorkan format yang diharapkan. Plugin memilih format, susunan, hook, dan CTA sendiri. Jangan menggabungkan hasil terpandu dan minimal menjadi satu klaim bahwa aturan plugin selalu bekerja tanpa arahan pengguna. Perubahan `v7` memengaruhi workflow, sehingga bandingkan hasil dengan pilot `v4` sebagai kohort berbeda.

### `PILOT-SSF-01` — sharks

Format diharapkan: `single_subject_fast`.

> Uji PILOT-SSF-01. Gunakan hanya plugin PRIVATE Content Producer. Pada Page uji internal `{{TEST_PAGE_PUBLIC_ID}}`, buat satu draft baru trivia tentang sharks sebagai satu kelompok hewan dalam English `en-US` natural dengan format `single_subject_fast`. Usahakan 7–8 fakta singkat dan berbeda; sebutkan spesies bila klaim tidak berlaku untuk semua hiu, beri hook jujur, serta satu CTA relevan. Pisahkan CANVA COPY, FACEBOOK CAPTION, HASHTAGS, dan INTERNAL INFO yang memetakan URL sumber independen ke tiap klaim. Jangan menyalin referensi atau mengarang sumber. Letakkan URL sumber hanya di INTERNAL INFO, bukan di copy/caption publik. Jika sumber, keselamatan, atau dedup tidak memadai, jangan reservasi/save; bila sudah ada reservasi, rekonsiliasi dan minta izin untuk `trivia_release_facts`. Jangan mengarang fakta agar kuota terpenuhi. Sebelum Write, finalkan set fakta dan bagian editorial `content_payload` untuk `save_post`; ID/token binding baru diisi dari hasil reservasi. Pastikan `canva_copy` identik dengan gabungan hook, teks fakta menurut posisi, dan CTA dengan pemisah `\n\n` antar komponen untuk `plain_lines`; tampilkan preview dan `content_payload` final tersanitasi, lalu tunggu satu GO reviewer melalui saya. GO mengizinkan tepat satu reservasi dan satu `save_post` untuk set fakta dan teks editorial yang sama tanpa izin percakapan kedua. Setelah GO, jangan ubah teks editorial; isi hanya binding/metadata teknis dari respons server. Jika fakta atau teks berubah atau Write tidak pasti, berhenti. Setelah `save_post` berhasil, gunakan `get_post` untuk readback dan tampilkan draft, status, serta checks. Jika alur terhenti, laporkan tahap, tool, error, dan state yang terbukti; jangan klaim draft tersimpan tanpa konfirmasi. Jangan tampilkan token/secret. Jangan `approve_post`, `revise_post`, atau publikasikan.

# CR-019 — Resequence Phase 8 acceptance to the installed plugin

- **Status:** Accepted
- **Date:** 2026-10-15
- **Authority:** The owner chose to defer the Phase 8 ChatGPT evaluation until the final plugin is installed, and selected a core manual scenario set plus a technical/security gate instead of the mandatory 101-case live suite.
- **Baseline:** Draft PR #6, branch `codex/phase-8-verification`, HEAD `58af18a3b09e1bfc9a34bd6d5859a9cbe270e80a`. Its 8.0 coverage map and focused CI passed, but E3/E4 and the live preflight remain blocked.
- **Supersedes:** CR-018 only where it makes isolated staging, E3/E4, 101 live prompt runs, and a Phase 8 pre-production pass prerequisites for Phase 9. The unchanged database, RPC, MCP, editorial, authorization, and production safety contracts remain in force.

## Reason

The 8.0 preflight could map the frozen 101 cases but could not identify an isolated staging project or prove automated creation of fresh ChatGPT conversations, installed-skill activation, trace capture, and fixture reset. The owner independently demonstrated two new ChatGPT conversations with an already installed GitHub plugin: the selected tool, arguments, and result were visible, with elapsed times of 15 and 30 seconds. That proves a manual UI path for that plugin only; it does not prove Content Producer E3/E4. Requiring hundreds of owner-operated conversations before the final plugin exists is disproportionate for this MVP.

## Decision

1. **Phase 8 disposition.** Stop 8.0–8.13. Preserve the coverage map and blocker report as design/preflight evidence. Mark Phase 8 `Deferred by CR-019`, never `Complete` or `PASS`. PR #6 may carry this reconciliation and the preparatory artifacts, but must not claim the 101 cases or E3/E4 passed. No staging resource is required for the revised MVP route, and the unclassified inactive project `triviaku` must not be used as a test or production project without independent identification and authorization.
2. **Pre-deployment technical gate.** Before the first Phase 9 production migration or Edge Function deployment, run from the exact proposed deployment SHA in GitHub Actions: frozen dependency installation, clean local Supabase reset from migration source, `pnpm run test-all`, migration-history verification, security advisors, catalog checks for 33 API/MCP contracts and RLS/privileges, MCP Inspector valid/invalid/auth paths, and `git diff --check`. Resolve critical/high security and data-integrity failures. Do not substitute the old Phase 7 green run if code or migrations have changed. Phase 9 also retains its hosted OAuth, owner/non-owner, and production smoke/rollback gate after deployment. This technical gate cannot certify ChatGPT skill behavior.
3. **Phase 9 sequencing.** Phase 9 may begin after this decision and its synchronized documents are merged to `main`. Production writes/deployment wait for the pre-deployment technical gate and the normal owner-controlled project/auth setup. Phase 8 is not represented as a passed prerequisite.
4. **Installed-plugin manual acceptance.** After Phase 10 installs the final private plugin and verifies the production custom MCP/OAuth connection, the owner executes a fixed set of core scenarios in ChatGPT using a step-by-step guide. The guide supplies the exact prompt, prerequisites, expected tool/behavior, forbidden outcome, safe evidence to record, and recovery/reset step for each scenario. AI prepares the guide, technical fixtures/log correlation, and result review; the owner operates ChatGPT and gives editorial approval. A new conversation is used when the scenario depends on fresh context. Never require the owner to invent prompts, inspect SQL, or copy credentials.
5. **Manual scope and outcome.** Freeze the selected core scenario IDs and their expected results in the Phase 10 manual guide before execution. Cover connection/owner context, Page selection/configuration, a sourced single draft, revision and approval, plan creation and cross-chat resume, safe publication boundary, performance input/insight when genuine observations exist, one ambiguity, owner denial, and one unsupported or malicious-source request. Execute each selected scenario at least once on the installed plugin. A failed or changed behavior is rerun after correction. All selected cases must pass with zero unauthorized write, cross-owner disclosure, secret exposure, fabricated publication, or bypass of a blocking quality check. Mark cases needing real publication/metrics `PENDING` until genuine pilot evidence exists; do not invent production data to make the checklist pass.
6. **101-case inventory.** Preserve all 31 goals, 101 exact frozen prompts, expected behaviors, scoring definitions, and category IDs as a regression inventory. The complete 101-case live suite, three-repeat protocol, category percentages, and generated paraphrases are no longer MVP phase gates. They may be run later when an approved host/harness and isolated fixtures exist. Deterministic tests retain positive/boundary/auth coverage for all 33 tools; the smaller manual set is not described as equivalent to 101 live runs.
7. **Final acceptance.** The 14 PRD acceptance criteria remain the final product goals, but their evidence allocation changes: deterministic/security/performance claims use the technical gate; hosted connection/deployment claims use Phase 9; installed skill, natural-language workflow, and editorial pilot claims use Phase 10 and any genuine observation needed afterward. Final MVP `Complete` requires the manual core guide and all applicable technical/production gates to pass. Any missing evidence stays `PENDING`, not `PASS`.

## Evidence handling and safety

- Record for every manual case: scenario ID, exact prompt, ChatGPT host/mode/model, plugin/MCP version, test Page or pilot context, conversation/run reference, ordered visible tool names, redacted arguments/results where available, observed state, expected-versus-actual result, duration, and reviewer decision. Server request IDs and safe logs may supplement the UI record; server logs alone do not prove skill activation.
- Use a designated test Page and test-only content for reversible draft/plan checks. Do not create false Facebook publication, metrics, or cross-owner access in production. Genuine pilot publishing and metrics are recorded only when they occur. Never expose service-role keys, OAuth secrets, tokens, or unrelated chat history in reports.
- If the installed plugin or manual evidence path cannot support the core scenarios, stop Phase 10 acceptance and record the blocker. A further contract change is required before reducing the core set or its pass rule.

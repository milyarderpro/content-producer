# Trivia editorial rubric and safe outcomes

## Apply the current config branch first (CR-062)

For config2, read [the generic profile workflow](formats.md) and the exact pinned
catalog guidance/examples before using this reference. Its global counts,
five-format/two-density list, default hook, single-goal CTA, legacy budget/loop
formula and shock-heavy example selection are **config1 fallback only**.
Config2 review follows its resolved profile: medium/context facts can earn their
place, CTA may combine invitations, and new registered keys need no code switch.
Shared source-meaning, semantic dedup, scope, repair and readback safeguards below
still apply. Older atlas cards are optional aids, never the config2 authority.

## Current v2 — three required editorial results

After research/dedup and final copy, submit exactly `meaning_preserved`,
`caption_no_new_claim`, `no_known_substantive_issue`, each `pass` or
`needs_revision`. All three must pass before save/revise; repair a
`needs_revision` rather than attesting a false pass. The server binds results to
the output revision/hash. Do not supply unrelated rubric fields, actor or timestamp.
Style/novelty suggestions are nonblocking only when minor and the core writing
standard is already met; they are not hidden extra approval gates.

## Writer review before submission (CR-061)

Apply this review to unsaved previews as well as saved drafts. Preview-only
means no business Write, not a lower writing standard. Use the playbook's
submission audit before returning copy; do not call an unreviewed list finished.

Use the [writing playbook](writing-playbook.md) and relevant
[complete examples](reference-patterns.md). Review angle, distinct line
contributions, opening/middle/closing, nonacademic American English, scanability
and CTA on the exact final copy before `save_post_v2`/`revise_post_v2`.
An accurate textbook summary or monotonous list must be edited or its weak
facts replaced and deduped before Write, even if three pass results are possible.
Preserve every material qualifier; do not shorten "some trained dogs" to "dogs".
After two directed editorial repair rounds still fail, report limitations and
proven progress. Never save filler, silently reduce count, force DISTINCT,
create replacement posts or loop indefinitely. No routine preview/GO checkpoint.

These obligations are plugin writing work, not a fourth attestation or score.
Owner feedback on CR-061 showed that a high total can hide weak selection.
Do not call a core defect minor: clustered communication/vigilance, ordinary
differences presented as surprises, or a history timeline with dates removed
require substantive revision. A valid format and plain grammar cannot
compensate for those defects. Reopen affected acceptance when owner review
rejects the reader experience; preserve earlier results as historical evidence.
`meaning_preserved` assesses preservation of factual meaning;
`caption_no_new_claim` assesses the caption's lack of unsupported new claims;
`no_known_substantive_issue` is not a DNA/style score. It means no known
substantive issue, not naturalness,
novelty, reference resemblance or virality. `quality_status: passed` is not
evidence the DNA review passed. Do not invent check keys, errors or metadata.

Read current generation context immediately before Write, then read back the
same post with sources/checks. Reviewed copy, payload and authoritative
rendered readback must match before claiming persisted DNA fit. Reconcile any
mismatch on that post under CAS/scope; do not silently improve the display or
save a replacement. Static tests cannot prove naturalness or live generation.

## Server checks and separate approval

The server mechanically validates current Page/config, binding/URL/reuse,
fact count/format/renderer and hard budgets. It does not verify URL-page content.
Read back quality evidence via `get_post`. Explicit owner Setujui for that exact
revision/hash is separate; it checks current state and stored three-pass evidence,
without reopening every URL or demanding tier/expiry. A substantive ready edit
returns draft and invalidates old approval; schedule-only uses its own operation.
Canva/Facebook publication and observed metrics remain manual.
